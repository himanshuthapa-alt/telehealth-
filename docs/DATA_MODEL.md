# Data model

Planned model: [BLUEPRINT.md](BLUEPRINT.md) §11. This file lists only tables that exist.

Schema: `apps/api/src/modules/*/*.schema.ts` (Drizzle, snake_case columns). Migrations: `apps/api/migrations/`, applied with `npm run db:migrate`.

| Table                     | Owner module              | Key columns                                                                                                                                                                                 | Notes                                                                                                                                                                                                            |
| ------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`                   | users                     | `id`, `phone` (unique, E.164), `full_name`, `password_hash` (argon2id), `role`, `consent_at`                                                                                                | One role per user. `consent_at` is null for provisioned staff.                                                                                                                                                   |
| `patient_profiles`        | users                     | `user_id` (PK → users), `date_of_birth`, `gender`, `preferred_language`, `district`                                                                                                         | All optional; the row is created on the first edit. No medical data here.                                                                                                                                        |
| `doctor_profiles`         | users (read by discovery) | `user_id` (PK → users), `specializations[]`, `languages[]`, `experience_years`, `bio`, `fee_inr`, `rating_avg`, `rating_count`, `photo_url`, `registration_number`, `is_demo`, `is_active`  | `registration_number` is private, never returned. Checks: ≥1 specialization and language, experience 0–70, fee ≥ 0, rating 0–5.                                                                                  |
| `availability_rules`      | scheduling                | `doctor_id`, `weekday` (1 = Mon … 7 = Sun), `start_time`, `end_time`, `slot_minutes`                                                                                                        | IST wall-clock times. Checks: weekday 1–7, start < end, slot 5–120 min. The API also rejects overlapping blocks.                                                                                                 |
| `availability_exceptions` | scheduling                | (`doctor_id`, `date`) PK, `reason`                                                                                                                                                          | Days off. Existing bookings that day are kept.                                                                                                                                                                   |
| `appointments`            | appointments              | `patient_id`, `doctor_id`, `start_at`, `end_at`, `status`, `reason_note`, `idempotency_key`, `cancelled_by`, `cancel_reason`, `cancelled_at`                                                | **No overlapping BOOKED appointments per doctor or per patient**: two `EXCLUDE USING gist` constraints (needs the `btree_gist` extension). Unique (`patient_id`, `idempotency_key`).                             |
| `consultations`           | consultations             | `appointment_id` (unique), `status` (WAITING/ACTIVE/COMPLETED/EXPIRED), `provider`, `provider_room_id`, `started_at`, `ended_at`                                                            | Created at the first join. No row = scheduled.                                                                                                                                                                   |
| `consultation_events`     | consultations             | `consultation_id`, `user_id`, `type` (JOINED/LEFT/RECONNECTED/VIDEO_FAILED), `at`                                                                                                           | Rejoin and no-show history.                                                                                                                                                                                      |
| `messages`                | consultations             | `id` (bigserial, also the chat cursor), `consultation_id`, `sender_id` (null = system), `client_msg_id`, `type` (TEXT/SYSTEM/PRESCRIPTION_CARD), `body`                                     | Unique (`sender_id`, `client_msg_id`): a retried send is never stored twice.                                                                                                                                     |
| `pharmacies`              | pharmacy                  | `name`, `address`, `is_demo`                                                                                                                                                                | One in the MVP.                                                                                                                                                                                                  |
| `medicines`               | pharmacy                  | `pharmacy_id`, `name`, `generic_name`, `form`, `strength`, `pack_size`, `price_paise`, `stock_qty`, `requires_prescription`, `is_active`, `is_demo`                                         | Money in paise (integers). Checks: price ≥ 0, stock ≥ 0.                                                                                                                                                         |
| `prescriptions`           | prescriptions             | `consultation_id`, `doctor_id`, `patient_id`, `status` (DRAFT/ISSUED/VOIDED), `general_instructions`, `valid_days`, `issued_at`, `valid_until`, `voided_at`, `void_reason`, `supersedes_id` | **Immutable once issued (DB trigger):** only ISSUED → VOIDED is allowed, nothing changes after that, and only drafts can be deleted. At most one draft and one issued per consultation (partial unique indexes). |
| `prescription_items`      | prescriptions             | `prescription_id`, `position`, `medicine_id` (null = not in catalog), `medicine_name`, `dosage`, `frequency` (enum), `duration_days`, `quantity`, `instructions`                            | Can only be added, changed or removed while the prescription is a draft (DB trigger).                                                                                                                            |
| `refresh_tokens`          | auth                      | `user_id`, `token_hash` (SHA-256, unique), `expires_at`, `revoked_at`, `rotated_at`                                                                                                         | `rotated_at` set = exchanged for a new token; presenting it again ends all sessions.                                                                                                                             |
| `password_reset_codes`    | auth                      | `user_id`, `code_hash`, `expires_at` (10 min), `attempts` (max 5), `used_at`                                                                                                                | Requesting a new code invalidates older ones.                                                                                                                                                                    |
| `audit_events`            | audit                     | `actor_id`, `actor_role`, `action`, `entity_type`, `entity_id`, `metadata`, `ip`, `at`                                                                                                      | Append-only: a trigger rejects UPDATE/DELETE. No foreign key, so it outlives what it logs.                                                                                                                       |

`role` is the Postgres enum `user_role` (`PATIENT`, `DOCTOR`, `PHARMACY_ADMIN`).

Enums: `prescription_status`, `frequency` (`ONCE_A_DAY`, `TWICE_A_DAY`, `THREE_TIMES_A_DAY`, `FOUR_TIMES_A_DAY`, `AT_BEDTIME`, `WHEN_NEEDED`), `medicine_form`, `appointment_status` (`BOOKED`, `CANCELLED`, `COMPLETED`, `NO_SHOW`), `appointment_party` (`PATIENT`, `DOCTOR`), `specialization` (8, from `SPECIALIZATIONS` in `packages/shared`), `gender` (`FEMALE`, `MALE`, `OTHER`, `PREFER_NOT_TO_SAY`) and `language` (13 Indian languages, from `LANGUAGES` in `packages/shared`). Adding a language needs a migration (`ALTER TYPE … ADD VALUE`).

**Deviation from §11:** the name lives on `users.full_name` (for every role) rather than on `patient_profile`. Doctors also keep their name on `users.full_name`.

**Slots are not a table.** Free slots are computed on request from `availability_rules`, minus days off, minus BOOKED appointments, minus anything starting within 30 minutes, up to 14 days ahead (`modules/scheduling/slots.ts`). Double-booking is prevented by the exclusion constraints, not by slot rows, so it holds even if a doctor changes their slot length between bookings.
