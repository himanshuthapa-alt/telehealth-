# Development

## Scripts (repo root)

| Script                | Does                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `npm run dev:api`     | API with reload (`tsx watch`)                                                              |
| `npm run dev:mobile`  | Expo dev server                                                                            |
| `npm run dev:web`     | Expo dev server opened for web                                                             |
| `npm run dev:android` | Expo dev server opened in an Android emulator                                              |
| `npm run dev:ios`     | Expo dev server opened in an iOS simulator (macOS required)                                |
| `npm run build:web`   | Export the single-page web app to `apps/mobile/dist`                                       |
| `npm run db:up/down`  | Start / stop PostgreSQL                                                                    |
| `npm run db:migrate`  | Apply migrations                                                                           |
| `npm run db:seed`     | Create the demo accounts (one per role)                                                    |
| `npm run check`       | Format check, lint, typecheck, tests. Run before every commit; this is also the CI script. |

New migration: edit `apps/api/src/platform/db/schema.ts`, then `npm run db:generate -w @telecare/api`.

## Conventions

- TypeScript strict everywhere. Prettier formats, ESLint lints.
- API: a new feature is a folder in `apps/api/src/modules/`, mounted in `app.ts`. Throw `AppError` for expected failures.
- Module shape: `*.schema.ts` (tables), `*.repository.ts` (interface + Postgres implementation), `*.service.ts` (rules, no SQL), `*.routes.ts` (validation with `parseBody` + HTTP). Services get repositories passed in; multi-table writes go through `inTransaction` (decision D1).
- Protect a route with `guards.requireAuth`, then `guards.requireRole('DOCTOR')` if needed. Read the caller with `getActor(res)`.
- Mobile: call the API through `api` from `@/lib/api` (adds the token and refreshes it). Forms use `useSubmit` and show `errorMessage()` text, never the server's message.
- Mobile data screens: fetch with a `useQuery` hook (see `features/account/profile-queries.ts`) and render through `<QueryState>`, which handles loading, empty, error, not-found and offline the same way everywhere. Don't build one-off spinners or error text.
- Offline data: a query is saved to disk only if its key starts with `PUBLIC_CACHE_KEY` (`'doctors'`). Never put personal or health data under that key. Public queries set `gcTime: PUBLIC_CACHE_MAX_AGE`, or they'd be dropped from memory (and the saved copy) after 5 minutes.
- `Screen` assumes a navigation header above it; a screen without one passes `edges={['top']}`.
- Typed routes: `.expo/types/router.d.ts` is generated by the dev server and is gitignored. If typecheck complains about a route you just added, run `npm run dev:mobile` once. On a fresh clone (CI) the file is absent and routes are untyped, so typecheck still passes.
- Anything both sides need (types, error codes) goes in `packages/shared`.
- Mobile: take colours, spacing and type from `src/ui/theme.ts`, never hard-code them.
- React and React DOM use the versions required by Expo SDK 58 in `apps/mobile/package.json`. Upgrade them only together with the Expo SDK.

## UI rules (designed for older people and people who read slowly)

The look: indigo ink on mint paper, marigold for the appointment token and for whatever is selected. Tokens live in `apps/mobile/src/ui/theme.ts`.

1. **Every action is an icon and a word.** Give each `Button` an `icon` from `features/shell/icons.ts`; never an icon alone.
2. **Everyday words.** Show specialties with `SPECIALTY[s].plain` ("Child doctor") and the medical name smaller underneath. Say "Bookings", not "Appointments" (it's the tab name).
3. **No meaning by colour alone.** Status, selection and banners pair colour with an icon and a word (selected chips get a tick).
4. **Big targets, big type.** Buttons are at least 56 dp (the main one 64 dp). Body text is 19. Text colours reach 7:1 contrast.
5. **One main action per screen:** one `variant="primary"` button.
6. **No sideways scrolling.** Use `TileGrid` / wrapping rows, not horizontal `ScrollView`s.
7. **The appointment is a token.** Show an active appointment with `AppointmentToken`; keep the marigold slip for that only.
8. **System font only** (no custom font downloads), which also renders Hindi when it's added.
