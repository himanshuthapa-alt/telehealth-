API tests need the database: `npm run db:up` first. **Each run starts from an empty test database**: `test/global-setup.ts` migrates `telecare_test`, then truncates every table (it refuses to touch a database whose name doesn't end in `_test`). The test setup migrates `telecare_test` before running. Each test uses a random phone number, so test files can run in parallel.

Screen tests mock `@/lib/api`, `expo-router` and `expo-network` (`jest.setup.js` supplies the official AsyncStorage mock). Two rules learned the hard way:

- **Wait properly for loads.** `renderScreen` waits until every query has _started and finished_ (`client.isFetching() === 0` is already true before the first fetch begins). TanStack then hands the result to React a moment later, so the first assertion after a load uses `findBy…`, not `getBy…`.
- **Clear the query client after each test.** Queries with a long `gcTime` (the doctor directory: 7 days) otherwise leave a timer that stops Jest from exiting.

- **Mock `expo-router` lazily** (`router: { push: (...a) => mockRouter.push(...a) }`): Jest builds module mocks before the test's constants exist.
- **After a load, flush TanStack's 0 ms notify timer inside `act()`** (see `renderScreen`), or late updates log act() warnings.

Prescription tests use **4 Jun 2029** (after the consultation tests' sweep date) and create their own pharmacy and medicines: tests never rely on seed data.

Consultation tests use a movable clock on **1 Jan 2029**, a year before the booking tests' dates, because their closing sweep touches every row whose window has passed. Test files hash the shared test password once (argon2 is slow on purpose; hashing per user made a concurrency test time out under load).

Booking tests in `apps/api` run with a fixed clock (`testApp({ now })`, Monday 7 Jan 2030 08:00 IST). The doctor search tests tag the doctors they create with a per-run token and search with it, because the test database keeps data between runs.
